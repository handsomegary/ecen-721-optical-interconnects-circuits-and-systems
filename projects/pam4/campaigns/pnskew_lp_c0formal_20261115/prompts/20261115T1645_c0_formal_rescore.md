## 判讀

1. 錯誤對計分窗很敏感：零偏斜的錯誤集中在早段（23／309 對 1／176），這部分符合你的推測。
2. 但這不是只有啟動暫態：
   - 早段和晚段的平均殘差幾乎相同，都是約 +0.36～+0.38，四案也一樣；
   - 晚段雖然錯誤少，殘差偏移仍在，錯誤全部判高。
   - 一個在早晚兩段、四案都固定的正偏移，比較像 payload 和訓練之間的系統差異，例如新 PRNG 種子的直流或位準分布不同、payload 的刺激振幅或偏移和訓練案不同，或 detector／FFE 的 bias 項。早段錯誤多，可能只是早段的碼型讓同一個偏移比較容易越過門檻。
   - 請用訓練案（phase −1 的 c0f_training_zero_cp00_phm1）同樣方式算帶符號殘差。如果訓練案接近 0、payload 是 +0.36，就是訓練和 payload 的不一致，不是電路問題。
3. 偏斜造成的部分（扣掉 +0.36 的共同偏移後）：
   - P 晚碼 0 的各階殘差從 +0.92 到 −0.46，是明顯的增益壓縮（低階往上、高階往下），符合偏斜造成的高頻損失。補償碼本來就應該處理這一部分。
   - N 晚碼 0 也有同樣形狀，但比較小（+0.77～−0.17）。
   - N 晚 +60 的形狀反過來（+0.11～+0.53），晚段錯誤 13→6、secondary 25→7。在晚窗內補償有效，而且形狀顯示可能略微過補。
4. P 晚：payload 只有碼 0，晚段 primary 29／176 錯誤，殘差呈增益壓縮，代表 −60 很可能有幫助。訓練窗的 primary RMSE 規則選了 0，但 payload 結果不支持這個選擇。這需要補 P 晚 −60 才能回答；我已經問使用者，結果會另外通知你。

- 先找出 +0.36 共同偏移的來源（比對訓練和 payload 的殘差、刺激與碼型）。如果是訓練和 payload 不一致，修好後用現有 raw 重算就好，不用重跑 Spectre。
